# 動画作品サイト

AIで制作した動画作品を、限られた人だけに見せるための個人サイトです。YouTube などの外部サービスは使いません。

- 大きなサムネを縦に1列に並べた一覧
- スクロールに合わせて進む背景（Blender の連番画像。まだ無い間は、プログラムで描く仮の背景）
- 長い作品向けの独自プレイヤー（続きから再生・10秒送り・速度・画質・全画面・キーボード操作）
- 作品のタイトルは **動画のファイル名（拡張子より前）をそのまま** 使用
- Cloudflare Access によるログイン制限（登録したメールアドレスの人だけ）

デザインの考え方は [`DESIGN.md`](./DESIGN.md) にあります。

---

## 1. まず手元で動かす

必要なもの：Node.js 20 以上、ffmpeg（`ffprobe` を含む）

```bash
npm install
npm run demo   # お試し用のダミー作品を media/ に作る（本物の作品があるなら不要）
npm run dev    # http://localhost:5173 で開く
```

## 2. 作品を追加する

```
media/
  videos/   夜の港.mp4          ← 動画。ファイル名（拡張子より前）がタイトルになる
  thumbs/   夜の港.jpg          ← サムネ。動画と同じ名前にする（jpg / png / webp）
  order.txt                     ← （任意）1行に1タイトル。書いた順に上から並ぶ
```

`media/` は Git に入りません（動画は大きすぎるため）。

```bash
npm run encode     # 動画を HLS に変換（回線に合わせて画質が自動で変わる形式）。変換済みは飛ばす
npm run manifest   # 作品一覧 media/works.json を作り直す
```

- 並び順は、`order.txt` に書いたものが先、残りはファイルの更新日時が新しい順です。
- `npm run encode` は時間がかかります（20分の動画で数十分が目安。PCの性能によります）。
  変換しなくても再生はできますが、20分を超える作品は変換をおすすめします（途中に飛んだときの待ち時間が短くなり、回線が遅い人でも止まりにくくなります）。
- サムネが無い作品は、タイトルの1文字目を表示した仮の画像になります。

## 3. 背景（Blender）を入れる

Blender でカメラが進む映像を PNG 連番で書き出し、次の場所に置きます。

```
media/bg/render/wide/0001.png …   横長（1920×1080）
media/bg/render/tall/0001.png …   縦長・スマホ用（1080×1920）※無くてもよい
```

```bash
npm run bg   # public/bg/ に WebP 連番と frames.json を作る
```

`public/bg/frames.json` があれば Blender の背景に、無ければ仮の背景になります。切り替えのための設定は不要です。
`public/bg/` は Git に入れてコミットしてください（サイト本体と一緒に配信されます）。

Blender 側のコツ（`DESIGN.md` の5章に詳しく書いています）：

- カメラはパスに沿って **一定の速度** で動かす（F カーブをリニアに）
- 24fps で 240 コマ前後。多くても 300 コマまで
- 画面の中央は暗めに（サムネが重なる場所なので）
- 横長と縦長は、同じ道筋・同じコマ数で書き出す

## 4. サイト名などを変える

[`src/config.js`](./src/config.js) を書き換えます。

| 項目 | 内容 |
|---|---|
| `siteName` | 最初の画面とヘッダーに出る名前（今は仮に `ARCHIVE`） |
| `tagline` | サイト名の上の小さな一行 |
| `pageTitle` | ブラウザのタブに出る名前 |
| `showLogout` | ログアウトボタンを出すか |

色・角丸・動きの緩急は [`src/styles/tokens.css`](./src/styles/tokens.css) にまとめてあります。

## 5. 公開する（Cloudflare）

サイト本体は **Cloudflare Pages**、動画は **Cloudflare R2**、ログイン制限は **Cloudflare Access** を使います。
※ Cloudflare の管理画面は名前や場所が変わることがあります。見つからないときは、項目名で検索してください。

### 5-1. R2 に動画置き場を作る

1. Cloudflare のダッシュボードで R2 を開き、バケット `film-archive-media` を作る（別の名前にする場合は `wrangler.toml` の `bucket_name` も変える）。
2. **公開アクセス（r2.dev の公開URL）は有効にしない。** 有効にすると、ログインなしで動画を見られてしまいます。
3. アップロード用に R2 の API トークン（読み書き）を作る。

### 5-2. 動画をアップロードする

[rclone](https://rclone.org/) を使います。インストール後、`rclone config` で R2 用のリモートを `r2` という名前で作ります
（種類は S3、プロバイダーは Cloudflare、5-1 のトークンと、アカウントの R2 エンドポイントを入力）。

```bash
npm run manifest
npm run upload -- --dry-run   # 何が送られるかを確認
npm run upload                # 実行
```

- 送られるのは、作品一覧（`works.json`）・サムネ・HLS です。HLS に変換済みの作品は、元の動画を送りません。
- R2 側にあって手元に無いファイルは、R2 から削除されます（消した作品を R2 からも消すため）。
- **作品を追加・削除したときは、この2つのコマンドを実行するだけ** で反映されます。サイト本体を作り直す必要はありません。

> ⚠ このアップロード用スクリプトは、実際の R2 に対しては動作確認をしていません。最初は必ず `--dry-run` で内容を確認してください。

### 5-3. Pages でサイトを公開する

1. Cloudflare Pages で、この GitHub リポジトリを接続する。
2. ビルドの設定：ビルドコマンド `npm run build`、出力ディレクトリ `dist`。
3. R2 との接続（`MEDIA` という名前でバケットを結び付ける）は `wrangler.toml` に書いてあります。
   反映されていない場合は、Pages の設定の「バインディング」で、変数名 `MEDIA`・バケット `film-archive-media` を追加してください。
4. できれば独自ドメインを設定する。

`/media/…` へのリクエストは、[`functions/media/[[path]].js`](./functions/media/%5B%5Bpath%5D%5D.js) が R2 から読んで返します。
サイトと同じドメインなので、ログイン1回で動画まで見られます。

### 5-4. Access でログイン制限をかける（必須）

1. Cloudflare Zero Trust を開き、Access のアプリケーションを追加する（種類：セルフホスト）。
2. 対象のドメインに、サイトのドメインを指定する。**独自ドメインと `〜.pages.dev` の両方** を守ること。
3. ポリシーを「許可」で作り、見せたい人のメールアドレスを登録する。
   ログイン方法は「ワンタイム PIN」（メールに届くコードを入力する方式）が手軽です。
4. アプリケーションの画面に表示される **Audience (AUD) タグ** と、チームのドメイン（`〜.cloudflareaccess.com`）を控える。
5. Pages の設定の環境変数に、次の2つを追加して、もう一度デプロイする。

| 変数名 | 値 |
|---|---|
| `ACCESS_TEAM_DOMAIN` | `あなたのチーム名.cloudflareaccess.com` |
| `ACCESS_AUD` | 手順4の AUD タグ |

この2つを設定すると、動画・サムネ・作品一覧を返す前に「本当に Access のログインを通ったか」をサーバー側で検証します。
万一どこかのドメインの保護を設定し忘れても、動画は見られません（一覧が「読み込めませんでした」と表示されます）。

### 5-5. 公開後の確認

- シークレットウィンドウでサイトを開き、**ログイン画面が出ること**（独自ドメインと `〜.pages.dev` の両方で）
- 登録していないメールアドレスではログインできないこと
- `https://あなたのドメイン/media/works.json` を、ログインしていない状態で開いても中身が見えないこと
- ログイン後、作品の再生・途中へのシーク・ログアウトができること

> ⚠ 5章の手順（Pages・R2・Access の組み合わせ）は、実際の Cloudflare 上では動作確認をしていません。
> 手元では、R2 の代役を使ったテスト（`npm test`）で、ファイルの配信・途中からの読み込み・ログイン証明の検証を確認しています。

## ファイル構成

```
index.html
src/
  config.js              サイト名などの設定
  main.js                全体のまとめ役（読み込み・スクロール・画面の切り替え）
  scroll-background.js   スクロール連動の背景（Blender連番／仮の背景）
  gallery.js             作品の一覧（スクロール連動の3D・マウスでの傾き）
  watch.js               視聴画面
  player.js              プレイヤー
  storage.js             視聴位置・音量の保存（見る人のブラウザ内）
  styles/                デザイン（tokens.css に色などの基準値）
functions/media/         /media/* を R2 から返す（Cloudflare Pages Functions）
server/access.js         Cloudflare Access のログイン証明の検証
scripts/                 作品一覧の作成・HLS変換・背景の変換・アップロード
tests/                   テスト
public/                  そのまま配信されるファイル（robots.txt、背景の連番）
media/                   元素材（Git には入らない）
```

## 知っておいていただきたいこと

- **視聴位置や音量** は、見る人それぞれのブラウザに保存されます。サーバーには送りません。別の端末には引き継がれません。
- **ダウンロードの防止** は完全にはできません（ログインした人が技術的に保存することは可能です）。見せる相手を限定することが、いちばんの対策です。
- **検索エンジン** には載らない設定にしています（`noindex`、`robots.txt`）。
- フォントはサイト内に同梱しており、Google などの外部サービスへの通信はありません。
